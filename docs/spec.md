# 仕様書（フェーズ1：代替テキストの表示）

> 企画書：`docs/planning.md`
> この仕様書はフェーズ1（代替テキストの表示）だけを対象とする。フェーズ2（AIによる提案）は別途作成する。

## 1. 設計思想

- 画面に出す警告や情報は最低限にする。
- 利用者にアクセシビリティの知識（WAI-ARIA やアクセシブルな名前の決まり方など）があることは期待しない。
- そのため、代替テキストの出どころ（alt / aria-label など）や、指定が複数ある・食い違っているといった情報は表示しない。

## 2. 対象とする要素

| 対象 | 例 |
|---|---|
| `<img>` 要素 | `<img src="..." alt="...">`（`<picture>` の中の `<img>` も含む） |
| `role="img"` が指定された要素 | `<div role="img" aria-label="...">`、`<svg role="img">`、`<span role="img">🍎</span>` |

### 対象外

- `role="img"` が指定されていない `<svg>`、`<canvas>`、`<input type="image">`、`<area>`、`<object>`、`<embed>`
- CSS の背景画像
- iframe の中のページ
- Shadow DOM の中の要素
- 画面に表示されていない要素（`display:none`、`visibility:hidden`、幅か高さが0のもの、およびそれらの中にあるもの）
  - ※ `aria-hidden="true"` は「画面には表示されている」ので対象外にはしない（下記の「代替テキストがない」として扱う）

## 3. 代替テキストの求め方

代替テキストは、W3C の「Accessible Name and Description Computation」（アクセシブルな名前の計算）と HTML-AAM に従って求める。

上から順に調べ、最初に見つかったものを代替テキストとする。

1. 要素自身または祖先に `aria-hidden="true"` がある → **代替テキストなし**
2. `role="presentation"` または `role="none"` がある（ただし、`aria-label` / `aria-labelledby` があり、ARIA の規則で role が無視される場合は除く）→ **代替テキストなし**
3. `aria-labelledby` が指定されていて、参照先から求めたテキストが空でない → そのテキスト
   - 参照先が複数あれば、指定順に半角スペースでつなぐ
   - 存在しない id は無視する
   - 参照先が画面に表示されていなくても、テキストとして使う（仕様どおり）
4. `aria-label` が空でない → その値
5. `<img>` 要素で、`alt` 属性が空でない → その値
6. `title` 属性が空でない → その値（`<img alt="" title="...">` の場合も `title` を名前にする）
7. 上のどれにも当てはまらない → **代替テキストなし**

- 「空でない」とは、前後の空白を取り除いたあとに1文字以上あること。
- `alt=""`、`alt` 属性がない、`role="img"` の要素で中に文字や絵文字がある（中の文字は名前に使われない）は、いずれも「代替テキストなし」になる。
- 表示する時は、連続する空白や改行を1つの半角スペースにまとめる。

## 4. 表示

### 表示モード

| モード | 内容 |
|---|---|
| 画像を消す（標準） | 対象の要素を消し、その場所に代替テキストを表示する。表示の大きさは中身（テキスト）に合わせる（画像が読み込めなかった時の見え方に近い） |
| 画像も表示する | 対象の要素を表示したまま、要素の左上に重ねて代替テキストを表示する（ページのレイアウトを変えない） |

- `role="img"` の要素を消す時は、中の要素（SVG や絵文字など）ごと消す。

### 表示する文字

| 状態 | 表示する文字 |
|---|---|
| 代替テキストあり | 代替テキストそのもの |
| 代替テキストなし | 「スクリーンリーダーユーザーなどには意味が伝わらない画像がここにあります」 |

- どちらの場合も、同じ大きさ・同じ見た目で表示する（文字の内容だけで区別する）。
- 表示する文字は `textContent` で入れ、HTML として解釈しない。
- 「代替テキストなし」の文言は `_locales` で日本語・英語を用意する。

### 表示の見た目

- 表示用の要素は Shadow DOM の中に作り、ページ側の CSS の影響を受けないようにする。
- 文字と背景のコントラスト比は 4.5:1 以上にする。
- 長い代替テキストは折り返して、すべて表示する（省略しない）。

## 5. オン・オフ

- オンにすると、その時点でページにある対象要素すべてに表示を行う。
- オンにした後でページに追加・変更された要素（スクロールで読み込まれる画像など）には対応しない。最新の状態で表示し直したい場合は、一度オフにしてからオンにする。
- オフにすると、ページを完全に元の状態に戻す（拡張機能が加えた要素・スタイルを残さない）。
- 対象は今開いているタブだけ。ページを移動したり再読み込みしたりした場合は、オフの状態に戻る。

## 6. ポップアップ

- 表示のオン・オフを切り替えるボタンを置く（オン・オフの状態がスクリーンリーダーにも伝わるように `aria-pressed` を使う）。
- 表示モードを選ぶラジオボタン（「画像を消す」「画像も表示する」）を置く。表示中にモードを変えたら、すぐに表示に反映する。
- 選んだ表示モードは `chrome.storage.local` に保存し、次回以降もそのモードを使う（初期値は「画像を消す」）。
- ポップアップを開いた時、今のタブで表示がオンかどうかを反映する。
- 拡張機能が動かせないページ（`chrome://` で始まるページ、Chrome ウェブストアなど）では、「このページでは使えません」と表示し、操作できないようにする。
- キーボードだけで操作でき、文言はすべて `_locales` で日本語・英語を用意する。

## 7. permissions

| permission | 理由 |
|---|---|
| `activeTab` | ポップアップで操作したタブだけに、一時的にアクセスするため |
| `scripting` | そのタブに、表示用のスクリプトを入れるため |
| `storage` | 選んだ表示モードを保存するため |

`host_permissions` は使わない。

## 8. 使用するライブラリ

アクセシブルな名前の計算には、外部のライブラリを使う。信頼できるものを慎重に選ぶため、次の基準で選定する。

| 基準 | 確認すること |
|---|---|
| 仕様への準拠 | Accessible Name and Description Computation に沿って実装されているか。テストが整っているか |
| 実績 | 広く使われているか（利用数、ほかの有名なツールでの採用） |
| 保守 | 継続的に更新されているか。不具合の報告に対応しているか |
| 依存 | ほかのライブラリへの依存が少ないか（依存が多いほど、混入するリスクが増える） |
| ライセンス | MIT License の本プロジェクトに同梱できるか |
| 大きさ | 拡張機能に同梱して重すぎないか |
| 安全性 | 既知の脆弱性がないか。外部への通信や、動的なコード実行（`eval` など）をしていないか |

- ライブラリは拡張機能の中に同梱する（外部から読み込まない）。
- 同梱するファイルの入手元・バージョン・ライセンスを記録する。

dom-accessibility-api の確認結果：

- 配布ファイルに `eval`・`new Function`・外部への通信（`fetch` など）は含まれていない。
- `<img>` は `alt` が空（空白のみを含む）の場合に `title` を名前に使う。本仕様の「`<img alt="" title="...">` は `title` を名前にする」と一致する。
- npm の Trusted Publishing（GitHub Actions からの公開）に切り替えられており、公開経路が確認できる。
- 注意点：メンテナーが1人で、リリースの間隔が長い（直近は 2024-07 → 2025-11）。
- 注意点：配布ファイルは複数のモジュールに分かれているため、拡張機能の content script で使うには、1つのファイルにまとめる（バンドルする）必要がある。
